Finding: Service account key storage in repo path
- Severity: High
- Location: DEPLOYMENT.md:88
- Issue: Guide directs copying the downloaded service account key into `data/keys/...` inside the repo with no guardrails.
- Impact: High risk of accidentally committing long-lived credentials that grant BigQuery/Storage write and logging rights across environments.

Finding: Workflows re-scan full request backlog each cycle
- Severity: Medium
- Location: src/orchestrator/etl-2.orchestrator.js:116, src/orchestrator/etl-3.orchestrator.js:38, src/orchestrator/etl-4.orchestrator.js:39
- Issue: After removing the testing filters, each `while (true)` loop now fetches up to 500 requests every 30s with no pagination/offset advance and rechecks BigQuery existence for already-processed items.
- Impact: Creates a hot loop that repeatedly hits Garoon and BigQuery with duplicate reads, wasting API quota and adding latency without progressing work when queues are empty.
- Recommendation: Persist and advance an offset/lastProcessedAt per workflow (or use Garoon pagination cursors), break the loop when no new work is found, and cap batch retries to avoid unnecessary scans.
